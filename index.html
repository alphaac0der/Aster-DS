Getting Started · Overview

Introduction

Aster is a zero-dependency, token-first design system engineered with dual interfaces derived from an authoritative source of truth: human-facing documentation and components for developers and designers, and machine-readable contracts for AI coding agents.

Zero Runtime Dependencies 109 Canonical Tokens 21 Components WCAG 2.2 AA

What is Aster DS?

Aster is an interface system designed to solve the growing coordination problem between human product teams and autonomous AI coding agents. Unlike traditional UI component libraries that tie developers to proprietary framework runtimes or heavy build steps, Aster delivers pure, browser-native web standards: W3C Design Tokens Community Group (DTCG) custom properties, native HTML5 classes, and idempotent browser ES modules.

Aster acts as a single authoritative source of truth. Design decisions flow downstream into CSS variables, browser behaviors, Figma variables, and structured agent instructions without manual translation.

The Problems We Solve

1. Token & State Drift

Design tokens often desynchronize between Figma files, CSS stylesheets, and documentation. In Aster, tokens are defined once in tokens/ and automatically compiled to CSS custom properties and Figma variable payloads.

2. Framework Lock-In & Runtime Bloat

Many design systems require React, Vue, or Angular wrappers. Aster components are built with standard HTML5 elements, CSS custom properties, and zero-dependency ES modules that drop into any stack or framework.

3. AI Agent Hallucinations

AI coding assistants frequently invent invalid CSS classes, guess non-existent component properties, or pick arbitrary colors. Aster gives agents strict machine-readable contracts in AGENTS.md and verified workflow skills.

4. Inconsistent Accessibility

Aster enforces automated mathematical contrast verification (WCAG 2.2 AA), standard 40px/44px touch targets, full keyboard traps and focus rings, and vestibular-safe reduced motion across all components.

Design Philosophy & Core Principles

Aster's visual foundation and component kinetics are built on five non-negotiable architectural principles:

Strict Semantic Token Precedence

Components and application views bind exclusively to semantic tokens (--as-semantic-color-*), density tokens (--as-density-*), and structural tokens (--as-space-*, --as-radius-*). Primitive tokens exist solely as internal definitions.

Explore Color System →

Single Standard Density

Aster enforces a single standard density scale. Control heights are 40px for buttons and 44px for inputs and table rows, ensuring comfortable touch targets that exceed WCAG SC 2.5.8 requirements.

Explore Density & Themes →

Four-Role Expressive Typography

Headlines use Bebas Neue for heroic impact, interface copy uses Manrope for legibility, tabular metrics and code use Space Mono, and editorial callouts use Merriweather.

Minimum 4px Corner Radius

Aster enforces a strict minimum 4px radius policy (--as-radius-sm). Buttons and badges use full 9999px pills; cards and dialogs use 8px to 16px. Zero 2px radii exist in the system.

Zero-Dependency Browser Approach

Aster components require no React, Vue, Svelte, or runtime compiler. Styles are delivered via standard CSS Custom Properties, and interactive behaviors (such as pointer-origin hover spotlights, dialog focus traps, and accordion expansion) use lightweight, idempotent event delegation initialized with a single function:

Browser Initialization
import { initAsterComponents } from 'aster-ds';

// Initialize delegated behaviors across the document tree
initAsterComponents(document);

Because Aster relies purely on standard HTML and CSS, it integrates seamlessly into static sites, SSR frameworks (Next.js, Remix, Astro), and legacy applications alike.

Installation & Quickstart

How to install, import, and configure Aster DS in modern web applications using npm or direct browser distributions.

Package: aster-ds Version 0.0.1 Zero Dependencies ESM + CSS

1. Prerequisites

Before installing Aster DS, ensure your environment meets the following requirements:

Node.js & Package Manager

Node.js 18.0.0 or later (Node 20+ recommended). Compatible with npm (v9+), pnpm (v8+), or yarn (v1.22+ / v3+).

Browser Compatibility

Modern evergreen browsers supporting CSS Custom Properties, :focus-visible, :has(), HTML5 <dialog>, and native ES Modules (Chromium 105+, Firefox 110+, Safari 16.4+, Edge 105+).

Package vs. Direct Browser Usage: If you use a modern bundler (Vite, Next.js, Astro, Webpack, esbuild), install via npm. If you are building a static website or prefer zero build steps, jump to Direct Browser / Static Installation below.

2. Install using npm

Install the official Aster DS package from the npm registry:

Terminal · npm
npm install aster-ds

Or using your preferred package manager:

Terminal · pnpm / yarn
# pnpm
pnpm add aster-ds

# yarn
yarn add aster-ds

3. Import Styles and JavaScript

Aster DS exports both pre-bundled and modular stylesheets, as well as an idempotent JavaScript behavior initializer:

JavaScript / TypeScript Entry Point (e.g. main.js / app.tsx)
// 1. Import all-in-one stylesheet (tokens + base reset + 21 components)
import 'aster-ds/aster.css';

// Alternatively, import individual stylesheets fine-grained:
// import 'aster-ds/tokens.css';
// import 'aster-ds/components.css';

// 2. Import and initialize component behaviors
import { initAsterComponents } from 'aster-ds';

// Initialize delegated event listeners on the document root
initAsterComponents(document);
Idempotent Event Delegation: initAsterComponents(root, options) uses delegated event listeners attached to the root node. It is safe to call multiple times or invoke on dynamically updated subtrees without duplicating event listeners.

6. Verification & Troubleshooting

Verify that your Aster installation is active and functioning with these quick checks:

1. Inspect Token Resolution

Open browser DevTools (F12) on your page. Inspect <body> and check Computed Styles for --as-semantic-color-interactive-primary. It should evaluate to #0f0f0f in light mode or #ffffff in dark mode.

2. Inspect Interactive Hydration

Move your cursor over an .as-button. The button should track pointer position via --x and --y inline variables to render the kinetic radial spotlight fill.

3. Verify Dark Mode Theming

Set data-theme="dark" on your <html> tag. All 109 tokens should dynamically recalculate surfaces, text inks, and borders without page reload.

4. Common Pitfalls

Unresponsive buttons: Ensure initAsterComponents(document) is invoked inside a <script type="module">.
Broken styles: Ensure aster.css is loaded before application overrides.

- **Horizontal Padding:** 16px horizontal (--as-space-4)

## 5. Non-Negotiable Aster Constraints
1. **Zero Primitive Color Leaks:** Bind colors strictly to `--as-semantic-color-*` custom properties. Never use `--as-color-primitive-*` or hardcoded hex values in component usage.
2. **Minimum 4px Radius Policy:** Never use `2px` border-radius. Use `--as-radius-sm` (`4px`), `--as-radius-md` (`8px`), `--as-radius-lg` (`12px`), or `--as-radius-full` (`9999px`).
3. **Single Standard Density Mode:** Compact mode (`data-density="compact"` / `.as-*--compact`) is permanently retired. Do not emit compact classes or attributes.
4. **WCAG 2.2 AA Accessibility:** Maintain >= 4.5:1 text contrast, >= 3:1 UI/border contrast, >= 24x24px interactive hit targets, and full keyboard operability (`Tab`, `Enter`, `Space`, `Escape`, Arrow keys).

Designer Blueprint & Architecture Specification

4pt Spatial Precision
01

Spatial Grid & 4pt Alignment System

The 52px trigger header height bounding envelope adheres strictly to Aster’s 4pt baseline grid (Base Unit = 4px). Standard touch targets (40px) and large interactive touch targets (56px) are exact multiples of 4 and 8. This guarantees pixel-perfect subpixel rasterization on standard 1× displays and crisp anti-aliasing across high-DPI (2×/3×) Retina viewports without fractional blur.

02

Box Model & Hatched Negative Space Zones

The 45° diagonal hatched areas (#D9A7F7) in the blueprint illustrate protected interior padding (16px horizontal (--as-space-4)). On components with full pill curvature (Radius.Full = 9999px), the circular capsule ends intrude deeply into the rectangular bounding envelope. 24px horizontal padding prevents typography and icons from visually colliding with the boundary curve.

03

Internal Layout Slots & Micro-Spacing

Interior child slots are isolated in lavender dashed bounding containers (#D9A7F7). The 16px × 16px rotating chevron (180deg when expanded) enforces the Gestalt law of proximity, cognitively binding the Phosphor glyph and text into an indivisible action unit. Constraining the icon container to a fixed square prevents layout shift when glyphs change.

04

Curvature & Concentric Radius Mathematics

Curvature follows the mathematical concentric radius rule: R_outer = R_inner + Padding. Interactive action controls employ continuous capsule curvature (12px container (--as-radius-lg)) to maximize affordance, while containing surfaces (cards, modals) scale to 8px (--as-radius-md) or 12px (--as-radius-lg), eliminating awkward corner pinch.

05

Kinetic State Machine (5 Active Layers)

Aster components implement Shade-DS layered kinetics:
• Layer 1 (Idle): Surface fill with 1px border glow.
• Layer 2 (Hover): Radial cursor spotlight at (--_x, --_y) expanding to full diameter.
• Layer 3 (Press): Tactile scale(0.97) translateY(1px) physical compression (80ms).
• Layer 4 (Focus): 2px solid focus ring + 2px offset (WCAG 2.4.7/2.4.11).
• Layer 5 (Success): Emerald glow (#10b981) + Phosphor checkmark, auto-decaying in 2000ms.

06

# Aster Component Implementation Prompt — Tooltip

## 1. Component Purpose & Canonical Role
- **Component:** Tooltip (`tooltip`)
- **Category:** Feedback & Status
- **Native Element:** `<div role="tooltip">`
- **Summary:** Contextual micro-copy bubble with 4px corner radius adhering to WCAG 2.2 SC 1.4.13 with Escape dismissal.
- **When to Use:** Clarifying icon buttons or terse technical abbreviations.
- **When Not to Use:** Interactive content or buttons inside the floating panel (use Popover).

## 4. Exact Geometry & Token Bindings (Standard Density)
- **Height:** Content-dependent (min 28px)
- **Horizontal Padding:** 12px left / 12px right (--as-space-3)
- **Vertical Padding:** 4px top / 4px bottom (--as-space-1)
- **Corner Radius:** 4px (--as-radius-sm)
- **Typography:** Manrope · 12px (--as-typography-font-size-xs) · 500
- **Icon / Secondary Control:** 8px offset above trigger (bottom: calc(100% + 8px))
- **Focus Ring:** Triggered via hover or :focus-within; dismissed via Escape

## 5. Non-Negotiable Aster Constraints
1. **Zero Primitive Color Leaks:** Bind colors strictly to `--as-semantic-color-*` custom properties. Never use `--as-color-primitive-*` or hardcoded hex values in component usage.
2. **Minimum 4px Radius Policy:** Never use `2px` border-radius. Use `--as-radius-sm` (`4px`), `--as-radius-md` (`8px`), `--as-radius-lg` (`12px`), or `--as-radius-full` (`9999px`).
3. **Single Standard Density Mode:** Compact mode (`data-density="compact"` / `.as-*--compact`) is permanently retired. Do not emit compact classes or attributes.
4. **WCAG 2.2 AA Accessibility:** Maintain >= 4.5:1 text contrast, >= 3:1 UI/border contrast, >= 24x24px interactive hit targets, and full keyboard operability (`Tab`, `Enter`, `Space`, `Escape`, Arrow keys).
